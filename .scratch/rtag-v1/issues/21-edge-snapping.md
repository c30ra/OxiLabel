# 21: Edge snapping for freehand lines and the brush

**What to build:** Freehand drawing and the brush can follow edges in the image, like GIMP's intelligent scissors. While dragging a freehand polyline with edge snapping on, the line follows the strongest nearby edge (live-wire: a cheapest path over an edge-strength cost map between the last anchor and the pointer) instead of the exact pointer path. The brush can be limited to a region bounded by detected edges, so a stroke fills up to a border without spilling over, with an optional offset that grows or shrinks the region by a number of pixels. Both are options of their tools (tool settings bar and options pie), off by default.

**Blocked by:** 08, 09

**Status:** done

- [x] Freehand polylines have an "Snap to edges" option: vertices follow the strongest edge near the pointer, still evenly spaced, and Shift-free drawing is unchanged when the option is off
- [x] The brush has a "Stop at edges" option: paint stays inside the similarity region grown from the stroke start (the same region growing and threshold as the fuzzy fill, ticket 22), with an optional offset in pixels (positive grows the region, negative shrinks it)
- [x] Analysis runs in the browser on lossless tiles of the viewed zoom level (ADR 0002); a zoom change mid-stroke applies from then on, and 6 MP+ images stay responsive
- [x] Snapping strength or search radius is adjustable, and a stroke can be drawn without snapping by holding a modifier
- [x] The tools analyse the original image; a per-tool switch to analyse the active enhancement filter's view is added with ticket 13
- [x] Edge detection and the live-wire path search are unit-tested in the core crate on synthetic images, and a browser test covers drawing along a synthetic edge

**Notes:** requested 2026-10-11. Decisions (grilling 2026-10-11, ADR 0002): computation in the browser with algorithms in `rtag-core`; the viewed level, not always full resolution; lossless PNG analysis tiles generated on first use per image; the original image by default with a per-tool switch for the filtered view; the edge-limited brush is bounded by a similarity region (shared with ticket 22), while live-wire uses an edge map. Build on the original image after ticket 09.

**Implementation note (2026-10-12):** decisions asked of the user: Shift held while drawing inverts the tool's option (with "Snap to edges" or "Stop at edges" on it draws freely, with it off it snaps), and the snap radius is in screen pixels (default 12). Core: `rtag_core::edges::EdgeMap` (Sobel strength over a window of one level, built from the loaded analysis tiles or naming the missing ones; `strongest_near`; `live_wire`, Dijkstra over 8-connected pixels where strong edges are cheap), `geometry::steps_along` (even spacing along a path) and `Bitmap::expanded` (grow or shrink by N pixels, a chamfer distance transform, linear in the area) and `keep_only`. UI: freehand polylines with "Snap to edges" (settings bar with Radius, and the options pie's north slot in freehand mode) snap their first point to the nearest edge and then place vertices every "spacing" along the live-wire path from the last vertex to the strongest edge near the pointer; until the view's analysis tiles are loaded the line follows the pointer. The brush's "Stop at edges" (settings bar with the shared fuzzy-fill Threshold and an Offset in image pixels; the brush options pie became an eight-slot pie for it) grows the similar region from the stroke's start (capped by the fill's Max) and paints only inside it, grown or shrunk by the offset; the region is grown again when the viewed level changes or tiles arrive, and Shift switches it off or on mid-stroke. Implementer's choice: the limit applies to the eraser too. Analysis tiles of the view are preloaded while the brush or freehand polyline is active. Measured in headless Zen on a 6240 × 4160 image: about 1–2 ms per pointer move for a snapped freehand line, about 5 ms for a limited brush stroke.
