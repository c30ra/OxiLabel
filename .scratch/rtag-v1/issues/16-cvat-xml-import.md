# 16: CVAT XML 1.1 import

**What to build:** I can import a CVAT "for images 1.1" XML export into a Project, mapping CVAT labels to rtag Labels and its boxes, polygons, polylines and points to rtag Annotations. A report lists unmapped labels and unsupported shapes before the import is committed.

**Blocked by:** 08, 10

**Status:** done

- [x] Importing an XML creates annotations on matching images, matched by file name
- [x] CVAT labels are mapped to existing labels or created on request, and attributes are carried over
- [x] A preview report lists unmapped labels, unmatched images and unsupported shapes, and nothing is written until I confirm
- [x] Formats tests use sample CVAT exports, including one from the author's `defect_detection` project, and check the resulting model

**Decisions (2026-10-17):** CVAT ellipses needed ellipses in rtag first (ticket 23, done before this). Annotations already on a matched image are kept or replaced as chosen in the preview, which says how many matched images have some. CVAT's `source` (manual, auto, semi-auto) is not kept: imported shapes count as manual work, having been reviewed in CVAT. The fixture from `defect_detection` is two images of `dataset_v2.zip`, renamed image1.jpg and image2.jpg, its meta cut to the label set (no owners, tasks or URLs).

**Implementation note:** `rtag-formats/src/cvat.rs` (`parse_cvat`) reads the XML with `roxmltree`: labels (CVAT type → allowed shapes, attributes → rtag attribute definitions, a number's values being min, max, step), and per image the shapes stacked by `z_order` (tags first): boxes (turned ones as oriented rectangles), polygons, polylines, points, ellipses with their rotation, masks (CVAT's runs are rtag's), tags; cuboids and skeletons are listed as unsupported. `rtag-server/src/cvat.rs`: `POST /api/projects/{p}/cvat-imports` (admin), multipart `file` (XML or a zip holding it) and `plan` (`rtag-core/src/import.rs`: per CVAT label map/create/skip, replace, commit). Without `commit` it reports and writes nothing; with it, it runs in one transaction (`BEGIN IMMEDIATE`) and bumps each changed image's version. Images match by file name, ignoring folders and case, then by size (same-named images of different sizes are told apart by it); unmatched, ambiguous and differently sized ones are listed. A label's suggested choice is the project label of the same name (ignoring case), else a new one. Shapes a label does not allow, outside the image, of skipped labels or unsupported, and attribute values with no matching attribute, are counted under "Left out". Saves and the import share `check_annotation`/`insert_annotations` (annotations.rs) and label creation `insert_label` (labels.rs). The project page has "Import annotations…" (admins). Checked on a copy of the dev database with the author's `annotations_original.xml` (237 images, 20 in the project): 1,136 annotations previewed in 0.02 s, nothing left out. A zip's `annotations.xml` is found in any folder (`__MACOSX` is ignored) and read up to the upload limit. A label listed twice is one label. Replacing changes only images that had annotations or get some; Import stays disabled with nothing to import or while a new label has a problem; the dialog numbers its requests so a late preview never overwrites a newer answer.

**Later (2026-10-17):** the author could not import: the export's photos sit in several folders and most were not in the project. The dialog got an optional **images folder** (typed, or picked in the desktop's dialog on the server's machine; resolved as image imports are, ADR 0003): export images the project lacks are looked for there by file name, in every subfolder, at the same size (resized copies are passed over; same-named same-size copies count as one image), and added to the project before annotating. The preview reads only image headers; committing reads and hashes the found images before the import's transaction starts. Checked on a copy of the dev database: the author's `annotations_original.xml` into an empty project with the `defect_detection` folder found all 237 photos (1.1 GB) and imported 7,697 annotations; the first preview took 21 s reading headers from a cold disk, later ones under a second.
